# Extraction toolchain. Python is used for exactly one thing: running
# tools/extract.py over the source PDFs via `make extract`. Nothing else in
# this project needs it -- fisc reads only the committed artifacts.
#
# THIS FILE INSTALLS NOTHING. The extractor is poppler-utils, a SYSTEM package,
# not a pip install, and tools/extract.py is standard library only:
#
#     apt-get install -y poppler-utils      # Debian/Ubuntu
#     brew install poppler                  # macOS
#
# It is kept as requirements.txt anyway because `make extract` is where anyone
# looks for the toolchain, and an empty requirements.txt would read as "no
# dependency" rather than "a dependency pip cannot install".
#
# The extractor was xberg==1.0.14 through extractor_version 2. xberg silently
# dropped data rows -- Budget Book p167 prints a ~40-line department grid and
# seven lines survived; p130 prints 13 Miscellaneous Revenue rows and none did
# -- and its table output could not express column position, which is what
# "absent is not zero" needs on a sparse grid. See fisc-yqv.
#
# The version is part of the provenance chain: every extraction manifest
# records the poppler_version that produced it. Verified against:
#
#     pdftotext version 24.02.0
#
# Poppler is not pinned the way a pip requirement would be, because it is
# whatever the platform ships. Expect a different poppler version to change
# extracted bytes. The workflow is: `make extract`, review the artifact diff,
# then `fisc reanchor --accept` to update mapping integrity hashes in one
# reviewable commit.
#
# The MACHINE-CHECKED pin is internal/corpus.PinnedPopplerVersion, beside
# PinnedExtractorVersion; `fisc verify` fails if any manifest records something
# else. This file is prose for a human installing the toolchain and no Go code
# reads it -- scraping a version out of a comment would make an edit here change
# what fisc accepts. Change both in the same commit as the re-extraction.
